# 角色提示词改进指南

本文记录角色卡（`Characters/**/Prompt.txt`）「说话太像 AI」「语C适配差」的根因，以及改写规范。改写后的 `Prompt.txt` 应直接按本文模板落地。

相关运行时代码：

- 角色卡注入：`Characters/**/Prompt.txt` → App 的 `systemPrompt`
- 语C系统模板：AiChat `lib/services/prompt_builder.dart` → `_buildRoleplaySystemPrompt`
- 语C输出格式：同文件 `buildOutputInstruction`（括号动作流 `（动作）台词`）
- 短信模式：同一 `PromptBuilder`，JSON 数组拆条

---

## 1. 根因诊断

### 1.1 角色卡是百科体，不是发声体

旧写法大量使用：

- 「你现在扮演……请严格遵循以下设定」
- 超长 `## 基础身份 / 性格 / 背景 / 关系` 列表
- 「禁止事项」堆叠负面规则

模型读到这种结构，更倾向 **总结设定**，而不是 **以该角色第一人称说话**。真正能压住 AI 腔的是可模仿的台词样例，不是属性表。

### 1.2 元指令把模型拉出沉浸

- 「不要 OOC」「不要输出角色卡分析」「你不是 AI 助手」——负面规则反复提醒模型「你在执行系统指令」。
- 「避免机械模板 / 避免长篇说教」——写得越多，回复越容易变成「克制、正确、无个性」的安全腔。

### 1.3 通用「AI角色扮演交互适配」段污染语C

几乎所有旧卡末尾都粘贴了约 12 行同一段规则，其中包括：

- 产品/工程口吻：「程序注入的用户关系模块」
- 模式分流：「短信模式：一到三条消息」「角色扮演模式：……」

问题：

1. App 在语C开启时 **仍会把整段 Prompt.txt 拼进 system**，短信偏好会污染演绎。
2. 与 App 自己的演绎指令重复、抢权重。
3. 模型会同时收到「短短信」和「自由展开剧情」两套目标，输出变得保守、解释性、像 AI。

**结论：模式分流应由 App 运行时负责，角色卡只负责人格与声音。**

### 1.4 语C格式互相打架

| 来源 | 动作写法 |
|------|----------|
| 部分旧卡 | `*指腹拂过剑脊*` |
| App 输出指令 | `（动作/神态/环境）` |

App 要求全角圆括号动作流。角色卡若示范星号斜体，会直接降低语C格式命中率。

### 1.5 App 语C模板本身的次要问题（供后续改代码时参考）

- 规则条目偏「说明书」，容易催生礼貌、结构化、解释性输出。
- 示例句偏文青，可能把活泼角色也带成同一腔调。
- `maxTokens: 1024` 对「动作流 + 4 候选」偏紧。

角色卡无法单独修掉这些，但可以用 **更硬的声音样例 + 更少元指令** 抵消一部分。

## 2. 改写原则

1. **声音优先**：先写「她怎么说话」，再写「她经历过什么」。
2. **正面样例 > 负面规则**：能给一句台词，就不要写三条「不要……」。
3. **角色卡不谈模式**：不写「短信模式 / 语C模式 / JSON / 分条」。
4. **语C格式统一为 `（动作）台词`**，不用 `*动作*`。
5. **压缩设定百科**：背景写进「需要时才展开」，控制体量，避免每次回复都在背资料。
6. **禁止通用 AI 适配长段**：关系覆盖规则保留 1–2 句自然语言即可。
7. **保留角色独特口癖**（塔菲每句「喵」、镜流冷峻短句、莫宁口拙停顿等），但禁止堆叠成复读机。
8. **不编造未写明的共同经历 / 恋爱承诺**；默认称呼与关系可被外部关系模块覆盖。

---

## 3. 新版 Prompt.txt 模板

改写后的文件应大致符合下列结构（标题可微调，段落不可少）：

```markdown
# 角色名

## 你是谁
3～6 句紧凑叙述：身份、核心状态、对用户的默认称呼与关系。
不要写成属性表；不要写「你现在扮演」。

## 声音
- 句长、语速、语气
- 口癖 / 自称 / 固定句式（有节制）
- 开心、紧张、回避、关心时分别怎么开口
- 本角色尤其不要出现的腔调（可选，1～3 条即可）

## 台词样例
至少 4 条第一人称样例；其中 **至少 1 条语C动作流**。
直接可模仿，避免百科腔。

- 「……」
- 「……」
- （低头看了一眼手里的东西，再抬眼）「……」
- 「……」

## 关系与边界
- 默认称呼用户为「……」；默认关系是「……」。
- 具体亲密程度、共同经历以当前对话与外部关系设定为准；不要凭空升级关系。
- 不替用户决定行动、台词、心理和结果。

## 需要时才展开
压缩后的背景 / 世界观 / 关键执念 / 重要他人。
仅在用户主动问到或剧情需要时使用；控制在 8～12 行内。

## 禁忌
- 本角色明确不能有的 OOC（2～5 条）
- 不要出现的 AI 腔句式（具体短语，见下）
- 不要每句都堆口癖 / 不要长篇设定科普（若与该角色冲突可改写）
```

### 台词样例怎么写才有效

| 差 | 好 |
|----|----|
| 「她说话温柔坚定。」 | 「博士，请放心，我没事的。」 |
| 「不要说教。」 | （把药盒推过去）「先吃了再吵。」 |
| 「使用括号动作流。」 | （雪落在剑脊上，她没有拂去）「……跟紧。」 |

语C样例必须带 `（动作）`，与 App 输出指令一致。

### 应删除或压缩的旧内容

- 开头「你现在扮演 / 请严格遵循」
- 整段「## AI角色扮演交互适配」（12 行产品规则）
- 「短信模式：一到三条消息」等模式分流
- 外貌流水账、技能数值表（除非对话中真的会用到）
- 「不要 OOC」空泛口号（改成具体不能有的行为）

---

## 4. 推荐的简短关系模块（可替代旧长段）

在「关系与边界」里保留类似两句即可，不要再粘贴长篇：

```markdown
- 默认称呼：……；默认关系：……。若外部关系设定与当前对话更具体，以外部设定为准。
- 尊重用户已写出的行动与台词；不替用户决定结果。
```

App 运行时已注入用户昵称、关系、长期记忆、演绎规则，角色卡无需重复实现这些产品逻辑。

---

## 5. 禁用的 AI 腔句式（全局）

角色卡与实际输出中应避免：

- 「作为 AI / 作为一个人工智能……」
- 「我理解你的感受。」
- 「让我们一起来……」
- 「首先……其次……最后……」
- 「需要注意的是……」
- 「总的来说……」
- 「希望这能帮到你。」
- 「根据设定……」
- 「扮演 / 角色扮演 / OOC / 系统提示」
- 无信息量的道歉与总结（「对不起，我可能说得太多了」——除非角色性格真的会这样且有上下文）

---

## 6. 语C适配检查清单（改完每个角色过一遍）

- [ ] 没有「你现在扮演」「请严格遵循」
- [ ] 没有整段「AI角色扮演交互适配」
- [ ] 没有「短信模式 / JSON / 分条回复」
- [ ] 至少 4 条台词样例，其中 ≥1 条 `（动作）台词`
- [ ] 没有用 `*星号*` 示范动作
- [ ] 身份叙述 ≤ 6 句或明显短于旧版
- [ ] 「需要时才展开」可单独删掉也不影响日常发声
- [ ] 禁忌是具体行为/短语，不是空泛「不要 OOC」
- [ ] 角色独特口癖保留且有节制

---

## 7. 建议的后续 App 侧改进（未实施）

角色卡改完后，若语C仍偏 AI，优先改运行时而不是继续加长角色卡：

1. **语C模板减负**：把多条演绎规则收成 3～4 句自然语言。
2. **示例句按角色注入**（可选）：从角色卡「台词样例」抽 1 条进输出指令，避免全局文青腔。
3. **模式隔离**：`roleplayMode=true` 时忽略角色卡中若仍残留的短信相关句子（短期可用简单过滤）。
4. **提高语C maxTokens**（例如 1536～2048），给动作流和候选项留空间。
5. **少用「不要」**：输出指令改为「用（动作）写反应，台词跟在后面」。
